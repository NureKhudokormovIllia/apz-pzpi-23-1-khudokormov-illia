3 ОПИС ВИКОНАНОЇ РОБОТИ
3.1 Загальні відомості про систему
Назва системи: Linux Kernel.
Розробник: Лінус Торвальдс та спільнота розробників Linux (з 1991 р.).
Призначення: ядро загального призначення для операційних систем сімейства GNU/Linux. Застосовується у серверах, вбудованих системах, мобільних пристроях (Android) та суперкомп’ютерах.
3.2 Архітектурний стиль системи
Ядро Linux є монолітним ядром із підтримкою динамічно завантажуваних модулів (Loadable Kernel Modules, LKM). Увесь привілейований код виконується в єдиному адресному просторі режиму ядра (kernel space), що забезпечує високу продуктивність завдяки мінімальним витратам на міжпроцесну взаємодію.
Обґрунтування вибору: монолітна архітектура дозволяє підсистемам напряму викликати одна одну без переключення контексту, що критично для операційних систем реального часу та високонавантажених серверів. Модульність забезпечує гнучкість: драйвери та файлові системи завантажуються й вивантажуються без перезавантаження.
3.3 Основні компоненти системи
Ядро Linux складається з таких ключових підсистем:
* Управління процесами (Process Management) — планувальник CFS (Completely Fair Scheduler), механізми створення, виконання та завершення процесів і потоків.
* Управління пам’яттю (Memory Management, MM) — віртуальна пам’ять, підкачка сторінок (paging), механізм Copy-on-Write, розподільники slab/slub.
* Віртуальна файлова система (Virtual File System, VFS) — єдиний інтерфейс для роботи з різними файловими системами: ext4, Btrfs, XFS, FAT тощо.
* Мережевий стек (Network Stack) — реалізація протоколів TCP/IP, UDP, сокетний інтерфейс BSD, netfilter для фільтрації пакетів.
* Підсистема вводу-виводу (I/O Subsystem) — рівні блокових і символьних пристроїв, черги запитів, планувальники I/O.
* Модулі ядра (LKM) — динамічно завантажувані компоненти для драйверів пристроїв, файлових систем та мережевих протоколів.
3.4 Взаємодія компонентів
Взаємодія між простором користувача (user space) та ядром відбувається через механізм системних викликів (syscalls). Процес у user space виконує інструкцію syscall (x86-64), що генерує переривання та передає управління обробнику в ядрі. Ядро виконує запитану операцію та повертає результат.
Підсистеми ядра взаємодіють напряму через функціональні виклики всередині kernel space. Наприклад, при відкритті файлу: VFS отримує запит → визначає конкретну файлову систему → звертається до блокового пристрою через I/O-підсистему → планувальник I/O оптимізує чергу запитів до диска.


3.5 Масштабованість та надійність
* Балансування навантаження: планувальник CFS рівномірно розподіляє процеси між ядрами CPU; підтримка NUMA (Non-Uniform Memory Access) для багатопроцесорних систем.
* Відмовостійкість: ізоляція помилок через простори імен (namespaces) та cgroups; watchdog-таймери для виявлення зависань ядра.
* Кешування: page cache для зберігання даних файлів у пам’яті; dentry cache та inode cache у VFS для пришвидшення доступу до файлів.
* Оновлення без перезавантаження: LKM дозволяє оновлювати драйвери без зупинки системи; механізм kpatch підтримує «живе» виправлення ядра.
* Контейнеризація: ядро надає namespaces (pid, net, mnt, uts, ipc) та cgroups — основу для Docker, Podman, LXC.
3.6 Приклади програмної реалізації
Для демонстрації архітектурного принципу модульності наведено приклад найпростішого LKM-модуля (Додаток В). Модуль реєструє функції ініціалізації та завершення через макроси module_init / module_exit — стандартний інтерфейс підсистеми LKM.
Запит до ШІ та повний код розміщено у Додатку В, а також завантажено у піддиректорію pzpi-23-1-khudokormov-illia-pract2 репозиторію GitHub.


4 ВИСНОВКИ
У результаті виконання практичного заняття:
* досліджено архітектуру ядра операційної системи Linux;
* визначено архітектурний стиль — монолітне ядро з динамічними модулями (LKM);
* описано шість основних підсистем: управління процесами, пам’яттю, VFS, мережевий стек, I/O та LKM;
* проаналізовано взаємодію компонентів через механізм системних викликів;
* оцінено переваги архітектури: висока продуктивність, гнучкість, масштабованість та підтримка контейнеризації;
* сформовано практичні навички архітектурного аналізу програмного забезпечення.
Монолітна архітектура ядра Linux з підтримкою LKM є оптимальним балансом між продуктивністю монолітних систем та гнучкістю мікроядерних. Саме ця архітектура зробила Linux провідною платформою для серверів, хмарних середовищ та вбудованих систем.

В.2 Програмний код модуля ядра Linux (hello_module.c)
 1  #include <linux/module.h>
 2  #include <linux/kernel.h>
 3  #include <linux/init.h>
 4  
 5  /* Ініціалізація модуля – викликається при завантаженні */
 6  static int __init hello_init(void)
 7  {
 8      printk(KERN_INFO "Модуль завантажено\n");
 9      return 0;  /* 0 = успіх */
10  }
11  
12  /* Завершення модуля – викликається при вивантаженні */
13  static void __exit hello_exit(void)
14  {
15      printk(KERN_INFO "Модуль вивантажено\n");
16  }
17  
18  module_init(hello_init);
19  module_exit(hello_exit);
20  
21  MODULE_LICENSE("GPL");
